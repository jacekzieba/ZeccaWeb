## Zależności: warunki alertów i granice wniosku

`dependencies.json` zachowuje pełny wynik registry npm z tego przebiegu. Liczby 1 critical + 3 high dotyczą **4 pakietów**, a nie czterech niezależnych podatności ani czterech potwierdzonych exploitów.

- [Next/sharp — komunikat maintainerów Next](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw): dotyczy podatnego parsera obrazów i określonego runtime Linux/glibc. Nie wykonywano szkodliwych plików SVG. W konfiguracji brak remotePatterns/dangerouslyAllowSVG, a użycia next/image wskazują lokalny PNG; to ogranicza widoczną ekspozycję, lecz nie naprawia podatnej zależności.
- [Server Actions DoS — komunikat maintainerów](https://github.com/vercel/next.js/security/advisories/GHSA-p3m5-59mp-jv5r): wymaga co najmniej jednej Server Action. Nie znaleziono `use server`; **nie przypisuję temu projektowi potwierdzonej ekspozycji**.
- Pozostałe alerty Next dotyczą SSG/ISR/self-hostingu. Projekt używa Vercel i dynamicznego root layoutu; nie wykazano podatnej ścieżki cache poisoning.
- [source-map-js](https://github.com/advisories/GHSA-68fv-2mgg-jv7q): wersja naprawiona 1.2.2; nie wykazano wejścia dla niezaufanych source map na produkcji.
- [Zod](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5): alert dla dużych walidowanych kolekcji; nie odtworzono memory exhaustion. Registry wskazuje naprawę przez przejście na 4.6.7, czyli zmianę major — wymaga migracji i testów, nie mechanicznego `audit fix --force`.
- [Supabase API keys](https://supabase.com/docs/guides/getting-started/api-keys): publishable key jest krótkim identyfikatorem klienta, nie sekretem. Jego obecność w bundle ani repo nie jest sama w sobie wyciekiem; kontrolę danych zapewniają granty, RLS i tożsamość użytkownika.
